# RLCD Photos 相册

[English](README.md) | [简体中文](README_ZH.md)

参照 C5-2.8 的 Photos APP，使用相同的 `espressif/esp_new_jpeg` 解码器和 `JPEG_PIXEL_FORMAT_RGB565_LE` 输出。版本固定为 C5 参考工程依赖锁中的 1.0.2。RLCD 在 JPEG 解码后做等比例缩放、灰度计算和 Floyd-Steinberg 黑白抖动，最后以 400 × 300 I1 图像交给 LVGL 全屏显示，图片预览页不显示顶栏。

## SD 卡与图片要求

BSP 使用 SDMMC 1-bit 访问 SD 卡：CMD = GPIO21（图中 MOSI）、CLK = GPIO38（SCK）、D0 = GPIO39（MISO）。此模式不需要 GPIO 控制 CS；R7 为 NC，GPIO17 不参与 SD 卡控制，D1/D2/D3 均不连接主控。初始化超时发生在读取文件系统之前，与 `photo` 目录或 JPG 格式无关。

| 项目 | 要求 |
| --- | --- |
| SD 卡文件系统 | 建议 FAT32；当前 IDF FatFs 未启用 exFAT |
| 图片目录 | SD 卡根目录下的 `photo` 文件夹，对应设备路径 `/sdcard/photo` |
| 文件扩展名 | `.jpg` / `.jpeg`，不区分大小写；只扫描该目录，不递归子文件夹 |
| JPEG 编码 | Baseline（基线 / 普通顺序式）JPEG、8 bit、RGB/YCbCr 或灰度；不支持 Progressive（渐进式）及 CMYK |
| 推荐尺寸 | 400 × 300；其他比例会等比例缩放并留白，不拉伸 |
| 大小上限 | 单文件不超过 2 MiB，原始宽 × 高不超过 2,097,152 像素 |
| 文件名 | 建议英文、数字及下划线；界面没有中文字库，非 ASCII 文件名显示为问号 |
| 文件数量 | 最多列出 128 张，按文件名排序；使用 `01_`、`02_` 等前缀方便排列 |

本实现没有启用解码器的旋转或硬件缩放选项，因此不要求源图片宽高为 8 或 16 的倍数。400 × 300 可以直接使用。PNG、BMP、GIF、HEIC 不在读取范围；仅修改扩展名不会转换图片格式。

直接使用手机原图时，设备端不处理 EXIF 自动旋转；先在电脑上转正并导出普通 RGB JPG。

```text
SD 卡根目录/
└── photo/
    ├── 01_demo.jpg
    ├── 02_landscape.jpg
    └── 03_portrait.jpeg
```

可先把本组件 `sdcard_example/photo/01_demo.jpg` 复制到 SD 卡的 `photo` 文件夹验证读卡和显示。该样图使用用户提供的相册图案，已导出为 400 × 300 的普通 RGB JPEG。

## 操作

- 开机时由设置服务在后台检测并尝试挂载 SD 卡、读取容量；桌面点 `Photos` 后复用共享挂载、扫描 `/photo` 并显示图片列表，选中图片后才解码。
- 点选照片后解码当前图片，并预加载前后邻图，保留此前的三张缓存切图方式。
- 点文件名全屏查看照片；照片按 400 × 300 区域等比例显示，完整保留图像，不裁切或拉伸。400 × 300 图片按原尺寸铺满屏幕，其他比例居中留白。列表页保留图标、Photos 名称和右上角白色返回箭头，图片页不显示顶栏。
- 向左滑动看下一张，向右滑动看上一张，首尾循环。
- 切图时继续保留旧照片，下一张准备好后一次替换；第一次进入且没有可显示图片时才显示加载提示。
- 从画面中间向上滑动回到列表；加载中或图片解码失败时也可返回。列表页返回箭头关闭 APP。
- 列表页 `Rescan` 清空缓存并重新扫描。没有 SD 卡、没有 `photo` 目录、空目录或图片无法解码时显示对应提示。
- Brookesia 底部系统手势继续可用；从桌面重新进入可恢复暂停的相册。

相册不会创建、删除或改写 SD 卡图片，当前工程关闭挂载失败自动格式化。开机尝试挂载 SD 卡，未就绪时相册可再次尝试；关闭相册时保留共享挂载；应用自己挂载的卡发生读取错误时，后续 Rescan 会尝试重新挂载。硬件没有卡检测引脚，不持续检测热插拔；建议关机后插拔，插卡后可在 Settings → SD Card 手动检测。

## 代码结构

```text
Photos.hpp / Photos.cpp        与 Games 一致的单例及 APP 生命周期
photo_init/                    列表、全屏查看、手势、三张缓存及后台结果更新
service/photo_service.c        后台任务、文件筛选、JPEG 检查/解码、RGB565 -> I1、预加载与取消
service/photo_service.h        数据类型、文件处理和后台服务接口
service/photo_result.c         解码结果和文件列表的统一释放
assets/image_photos_mono.c      用户提供的相册桌面图标，64x64 I1 C 数组
assets/image_photos_mono.png    对应黑白预览
sdcard_example/photo/          可复制到 SD 卡的示例图片
```

SD 读卡和 JPEG 解码在独立任务中执行，不持有 GUI 锁。APP 安装时只创建等待请求的工作任务；进入相册才提交扫描请求，选中图片才开始解码和邻图预加载。UI 每 20 ms 取一次完成结果，缓存命中直接在当前手势处理内换图。缓存保存最终黑白 I1 数据，不重复进行 JPEG 解码或黑白抖动。每张含调色板 15008 字节，三张缓存共 45024 字节；解码过程中另有 JPEG、RGB565 和待交接结果的临时内存。

缓存围绕当前选择保留前后图片，优先预加载最近滑动方向的邻图。一次只预加载一张；选择正在预加载的同一张时继续使用该任务，选择其他未缓存图片时新请求覆盖旧请求。后台在读卡结束、JPEG 解码结束处检查取消状态，已经运行的单次读卡/JPEG 解码/黑白转换不会被强行中断。过期结果不进入缓存或画面。更换缓存时保留仍在显示的旧图，直到新图准备好；预加载失败只记录该缓存项状态，不打断当前图片，也不无限重试。

从图片页返回列表会保留最多三张缓存，重新选择可复用；Rescan 会清空缓存以重新读取卡中内容，关闭 APP 释放缓存并取消请求。暂停时停止轮询和后续预加载，已在执行的任务可完成，恢复后再接收结果。SD 卡不会写入额外缓存文件。不进行开机照片预解析，也不保留跨 APP 生命周期的图片缓存；容量统计由设置服务在开机检测时完成。

BSP 使用 SDMMC 1-bit：CLK=GPIO38、CMD=GPIO21、D0=GPIO39，不使用 GPIO17/CS。屏幕驱动和刷新时序继续沿用现有配置。

## 性能日志

串口 `photos` 标签会输出真实设备上的分段计时：

- `Load` / `Prefetch`：用户请求 / 后台预加载；`read` 是打开和读取文件的耗时，`jpeg` 包含格式检查、分配解码缓冲和 JPEG 解码，`mono` 包含释放 JPEG 输入和黑白转换；单位均为微秒（us）。
- `UI ready ... cache=hit/miss, wait=... ms`：从当前图片请求到提交给 LVGL 的等待时间。缓存命中跳过读卡和解码；该数值不包含后续屏幕传输、扫描及液晶响应，不能当作整屏刷新时间。

首次打开或连续快滑到未缓存的图片仍需实际解码；缓存命中率和上板计时用于评估流畅度。

## 验证与编译

在 ESP-IDF 6.0.2 环境的工程根目录运行：

```text
idf.py build
idf.py flash monitor
```

应用镜像为 `build/esp32_s3_touch_rlcd_4_2b.bin`，首次烧录应通过 `idf.py flash` 同时写入 bootloader 和分区表。

完整使用流程见[出厂固件使用说明](../../README_ZH.md)。
